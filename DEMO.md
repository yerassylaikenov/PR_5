# DEMO.md — сценарий защиты (воспроизведение за ~10 минут)

Цель: открыть проект на ноутбуке и получить тот же результат, что при сдаче.
Порты фиксированы: RPC `8545`, web `5173`, монитор `8787`.

## 0. Подготовка

```bash
node -v        # ожидается v24.x (достаточно >= 22.10)
npm ci
npm --prefix web ci
npm run compile
```

Опционально: MetaMask (для Задания 1), Python + `slither-analyzer` (для Slither).

## 1. Четыре терминала

```bash
# Терминал 1 — узел
npm run node

# Терминал 2 — деплой и демо-данные
npm run deploy:local
npm run seed

# Терминал 3 — монитор
npm run monitor

# Терминал 4 — dApp
npm run web   # -> http://localhost:5173
```

> Для твоего формата есть готовые окна-терминалы по заданиям —
> папка `launchers/` (`task1_web.cmd`, `task2_tests.cmd`, `task3_monitor_load.cmd`,
> `run_all.cmd`): двойной клик открывает отдельное окно с галочками и красными
> пометками найденных уязвимостей/откатов.

## 2. Настройка MetaMask

1. Добавить сеть вручную: RPC `http://127.0.0.1:8545`, chainId `31337`, валюта ETH.
2. Импортировать 3 тестовых аккаунта Hardhat (приватные ключи печатает `npm run node`):
   - аккаунт #0 — **админ** (DEFAULT_ADMIN_ROLE),
   - аккаунт #1 — **оператор** (OPERATOR_ROLE),
   - аккаунт #2 — **расчётный центр** (SETTLEMENT_ROLE).

> ⚠️ Это **общеизвестные тестовые ключи** (мнемоника `test … junk`). Использовать
> их в реальных сетях нельзя — потеряете средства.

> После перезапуска ноды в MetaMask: Настройки → Дополнительно → «Очистить данные
> вкладки Активность» (иначе ошибка nonce).

## 3. Сценарий демонстрации

### 3.1. Web3-клиент (Задание 1)
1. «Подключить кошелёк» → виден адрес (кратко + полный по ховеру), `chainId 31337`,
   имя сети и **роль** (информационно).
2. Переключить сеть в MetaMask на другую → баннер «Неверная сеть», запись
   заблокирована, кнопка «Переключить сеть». Вернуть на 31337.
3. **Чтение:** `getPayment` для `PR5-OP-2026-000001`; `verifyDocument` — загрузить
   `demo-data/order-001.xml`, хеш считается в браузере, результат «совпадает».
4. **Запись (машина состояний):** оператором `registerPayment` (загрузить XML,
   указать сумму) — видно: Симуляция → Ожидание подписи → Отправка → Ожидание
   подтверждения → Успех, с `txHash`, `blockNumber`, `gasUsed`.
5. Расчётным центром `markExecuted` для `PR5-OP-2026-000003`.
6. **Отказ в подписи:** начать запись и нажать «Отклонить» в MetaMask →
   понятное сообщение «Вы отклонили подпись (4001)», не «unknown error».
7. **Негативный сценарий:** переключиться на **админа** (нет OPERATOR_ROLE),
   «Негативный сценарий» → симуляция откатывается с
   `AccessControlUnauthorizedAccount`, `totalRegistered` до = после.
8. **Лента событий:** записи `PaymentRegistered`/`PaymentStatusChanged` с `txHash`
   и блоком, по убыванию блока, без дублей.

### 3.2. Мониторинг (Задание 3)
```bash
npm run demo:alert    # R-1 срабатывает один раз, остальные подавлены cooldown
npm run demo:normal   # штатный поток, "alerts: 0"
```
В окне монитора (Терминал 3) при `demo:alert` видно красный **ALERT R-1 [HIGH]**.

### 3.3. CI
```bash
npm run ci:local      # компиляция + web build + тесты + slither + audit
```
Лог — `reports/ci/ci-local.log`. Журнал успешного запуска на GitHub — скриншотом.

### 3.4. Нагрузочный эксперимент
```bash
npm run loadtest      # профили A и B, метрики + SVG-графики
```
Сравнение A vs B, p50/p95/TPS и вывод об ограничивающем компоненте — в
`reports/load/SUMMARY.md`.

## 4. Если что-то пошло не так

- **Порт занят (8545/5173/8787):** закрыть старый процесс или перезапустить терминал.
- **Рассинхрон nonce в MetaMask:** «Очистить данные вкладки Активность».
- **Пустая лента событий после перезапуска ноды:** заново `npm run deploy:local`
  и `npm run seed`; при необходимости `npm run reset`.
- **Полный сброс состояния:** `npm run reset` (удаляет deployment, state монитора,
  логи мониторинга), затем деплой/seed заново.

## 5. Быстрая перепроверка перед защитой

```bash
npm run demo:all      # тесты + мониторинг-демо + нагрузка, обновляет reports/
```
